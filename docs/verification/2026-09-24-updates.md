# Workbench update delivery verification, 24 September 2026

Scope: the shared contributor/user update workflow in `docs/updating.md`. This implementation is based on the existing installed toolbar/menu baseline at `1528f93334c87a22d1bbf0b8212d7d5766f072f4` (PR #90), so accepting the update must not remove those tools.

## Observed

- Swift release build succeeded with pinned Sparkle 2.10.0.
- SwiftPM suite: 174 tests, zero failures. Core, update identity/activity, provider transport, refinement and browser regressions passed in the local full-suite run.
- Release tooling: 19 existing release tests, 11 installer tests and nine update tests passed after the latest packaging changes. Tests cover release/local separation, exact archive/receipt identity, feed enclosure URL/size/signature presence, cross-edition rejection and real OS file-lock contention, preservation of either existing Applications location and duplicate-copy refusal. Publication rechecks the actual signed package, archive/feed signatures, download/checksum records, and the tag's version and source before writing a release.
- Website: ten tests passed and static build succeeded. A synthetic next release changes download, checksum and notes links from one release record. Feedback no longer guesses the installed version from the website.
- Signed local candidate built and re-extracted. Its executable's update checks passed. The package contained Sparkle, its license and no public feed because it was correctly marked local/modified source. The candidate and installed Preview had identical designated requirements: existing Preview identifier, Apple generic trust and the same Developer ID team. This establishes signature identity continuity, not a new native permission-grant test.
- A subsequent clean signed candidate recorded source `4def1a2ce85671f5b20a59bf8b23329a1e051a47` with modified-source false. Its extracted bundle retained the installed verified Production cloud profile. It was not installed.
- Preview icon was extracted from the actual package and visually inspected: purple ground and a readable white P badge.
- Existing Developer ID and notarytool Keychain profile were accessible. The update private key was created in Keychain; only its public verification key is in source.
- An isolated executable compiled the actual `WorkbenchUpdates.swift` against pinned Sparkle and passed ten delegate-policy checks: busy deferral, a single idle resume, stale-handler removal after abort, a retained termination guard, quiet scheduled reminders and busy-check refusal. These checks now run in `--check-updates` and `--check-core`; the rebuilt release executable passed `--check-updates`. The updater was never started, so these checks made no network request or app replacement. This is callback-policy evidence, not an end-to-end update.

## Not yet established

The full StageKit run reached 146 tests / 2,961 assertions but had two shortcut-registration failures while the installed Workbench held those shortcuts. It must pass after an authorised quit; the failures have not been waived. The pre-existing live menu-bar popover check remains excluded by the suite's documented CI mode.

Two GitHub macOS runs aborted in the old native retargeting test at an asynchronous wait. Replacing the wait with a direct assertion exposed its invalid assumption: AppKit can complete the first animation before retargeting, so two total callbacks are legitimate. The test now checks the callback increment during the synchronous replacement. The existing separate test still checks for a stale animation callback after completion and dragging. Remote confirmation of this correction is pending.

The candidate has not been installed. Update Settings and prompts have not been accepted in the installed app. A real signed/notarized old-to-new Sparkle update, saved-state preservation through that update, busy-restart behavior, failed-download/signature handling in the actual updater, public download/readback, live feed deployment and legacy-binary retirement remain to be verified. Fresh-Mac first-use remains separate from testing on a release Mac with prior permissions.

No new public release or feed has been published. The website release record still points to the already published Preview 4. Source tests and a signed local package do not establish customer delivery.
