# Workbench implementation map

Workbench 2 combines the existing Voice and StageMark capabilities into one native app. It retains their useful boundaries: speech code owns speech state; StageKit owns drawing and presentation; the app owns lifecycle and shared entry points. This is a map of the current branch, not release or hardware-verification evidence.

The internal Swift module remains `LocalVoice` to preserve App Intents type/metadata compatibility. Packaging names the installed binary `Workbench`, or `WorkbenchPreview` in Preview. StageKit is linked into it; Workbench does not launch a second StageMark process.

`StageKitController` exposes views, actions, lifecycle and shortcut descriptors rather than its internal coordinator. Host callbacks route navigation, hide Home before presenting and coordinate busy state. StageKit must not create another menu-bar item or terminate the app independently. Embedded, the shared toolbar is Workbench's one drawing control surface, so the Draw page leaves out the standalone app's floating-palette settings (Show the palette while drawing, Board palette); their stored values stay for the standalone app.

The two modules still have their own internal `Workbench.swift` style helpers and share the appearance preference domain. They are not identical mirrored files. Keep their appearance consistent through the [product contract](workbench.md); do not extract a larger shared framework without a concrete need.

## Chrome destination adapter

The [presenter contract](presenter-direction.md#state-and-security-boundaries) owns Chrome/native routing. `DemoResource.browserTarget` is optional and machine-local; imported and exported libraries strip it. No mobile or SceneSyncKit source depends on PresenterKit. The bundled host has no state or command authority of its own; it forwards bounded native-messaging frames over a current-user Unix socket to the app. Each browser installation owns its UUID, site grants and temporary tab bindings. The app owns conflict/error handling and the existing keyboard catalogue owns Switch to. No network listener, Accessibility permission or backend is added.

## Native iPhone and iPad target

`Mobile/Workbench.xcodeproj` contains the separate **WorkbenchMobile** iOS/iPadOS 26+ target, generated by `scripts/mobile-project.py`. Its Preview identity is `com.ethdawg.workbench.mobile.preview`. It uses native SwiftUI/UIKit surfaces, not the Mac shell or a Catalyst target. [The mobile contract](ios-preview.md) owns its feature and evidence boundaries; the remaining Mac architecture in this document is unchanged.

`TextPrimitives.swift`, `DictationCleanup.swift` and `CorrectionRule.swift` from `Sources/LocalVoice`, plus the shared `Sources/PhotoHandoffKit` and `Sources/SceneSyncKit` files, are compiled into mobile. StageKit, AppKit, Carbon, FluidAudio, Mac model-server configuration and shell-based speech are not linked. Mobile assets and `library.json` live in its own sandbox. The separate SceneSyncKit manifest owns portable editable scenes, with optional same-account private sync. This does not sync transcripts, wallpaper projects or the entire resource library. Explicit selected-photo transfer uses its own account-bound store and transport; [photo-handoff.md](photo-handoff.md) owns that contract. Reuse shares an original asset by explicit choice while each image project owns its crop, ink and composition.

`scripts/test-mobile.sh` runs the native unit/UI targets with disposable Simulator state and prints the result bundle. Simulator tests, unsigned archives, development signing, physical-device acceptance and TestFlight distribution are distinct gates. The [mobile acceptance record](ios-preview.md#acceptance-record) reports the current result for each.

## Native surfaces and operation flow

`WorkbenchQuickPanel` owns fixed utility actions and the receipt/editor well. `WorkbenchControlState` projects each capability’s own facts for its panel row and Home’s Persona control; its full `live` state still feeds the toolbar’s global action priority. A row’s title, enabled state, active symbol and dispatched operation agree. The row keeps the rendered operation as its button identity and checks it against the current owners before dispatch, so an obsolete ending cannot become a new start. Its header's `PanelSwitch` is the Floating toolbar switch: an AppKit row whose words and full 32 point height toggle the native switch, which is the row's one accessibility element; the words take the header's text scale, and the row grows with them. Its `PanelRecoveryRow` shows the first sentence of an error or notice with a door to the page that shows it in full. The page is recorded with the problem where it is raised: `AppModel.report(_:on:)` keeps an `Attention` (message and `Attention.Page`), and StageKit's coordinator and settings store post a `StageNotice` with its `StageNoticePage`, which `StageKitController.noticePage` returns with the notice; persona and scene notices belong to their own pages. Nothing reads the words to choose a door. `KeyboardCoachModel` remains the only shortcut editor and conflict checker. NSPopover keeps the panel's SwiftUI content alive between visits and never delivers `onDisappear`, so `PanelShortcutEditor` holds the well's editor for one visit and `AppDelegate` ends it whenever the popover opens or closes; `PanelLeaveWatch` closes the panel on a mouse press in another app or when Workbench resigns active (`QuickPanelLifecycle.swift`). `PromptInsertionRunner` checks exact destination snapshots around every selected-text write and before the guarded `TextDelivery` paste fallback; its native adapter owns cancellation and temporary Escape monitors. `PromptPickerController` owns the one transient Saved Prompts panel: `PromptPickerList` freezes the prompts saved in Library, `PromptPickerLayout` bounds its width and placement, and `PromptPickerAction` inserts or copies only after the panel has closed, when `PromptFieldReturn` waits up to about a second for the frozen field to be in front again. The panel is sized from its content's `onGeometryChange` report. `PromptPickerChecks` covers them without a window; the surface gallery renders the picker's states and opens the production panel invisibly to check it is the size of its content. `DemoPresentation.makeControlsMenu()` and `PersonaLibrary.makeControlsMenu()` return native snapshots to the shared toolbar while their existing controllers retain lifecycle ownership. `StageKitController.personasView` exposes independent preparation; `onOpenPersonas` delegates navigation to the host. Scene-specific persona selection keeps its own sheet.


AppDelegate owns the normal window, status panel, commands, global voice shortcuts and embedded StageKit controller. WorkbenchHome owns the single page record and the Voice, Screen and Saved sidebar groups. Its destination resolver retains section routes for Library (Resources, Packs, From iPhone) and Settings (General, Keyboard, Models, Connections); Your dictionary belongs to Dictate, while Meetings now has its own sidebar destination. WorkbenchPageHeader reads names and symbols from that record. WorkbenchDesktopChrome owns shared hover/selection styling, the finite greeting and SidebarMetrics, the one icon column both sidebar widths share, whose names lay out at their expanded width and fade; the surface gallery fails if collapsing moves the toggle or any icon. SidebarHintTarget reports pointer entry/exit and the window draws collapsed hints outside the scrolling list. HomeJourney orders the first-use, current-work and recent-work sections; the four Home workspace cards only change the route. HomeRecentWork projects History All’s newest five through HistoryList and HistoryRowsCache. HistoryDoor targets one transcript without selecting it or replacing the Dictate draft. ContentView owns the Dictate settings and Read Voice & pace sheets; a PageFocusRequest for dictateOptions opens the same Dictate sheet once and consumes the request. The sheet is independently scrollable with Done and Escape dismissal. Persistent preferences retain their existing owners. LocalPersonaProfileView remains the Home Me control, backed by the existing Persona ID preference. The founder introduction appears only in Settings. Opening the app shows Home; closing its window leaves independent work running. Settings uses SMAppService.mainApp for optional login launch.

Meetings uses the existing MeetingModel and immutable transcript UUID. completedTranscriptID is published only after transcript and completion-journal commits; the completion card opens History through a typed HistoryDoor. New recording/retry clears the previous link. Successful History removal clears a matching link after its commit, while failed removal retains the transcript, audio and link. Choosing Microphone only explicitly enables that source before Start; changing sources never starts recording and is refused while capture is busy.

The portable studies in [docs/experience](experience/index.html) use synthetic state and scenario fragments. They are review tools, with no connection to app data, permissions, recording or provider calls. SurfaceGallery renders the actual SwiftUI pages and sheets under isolated preferences for implementation evidence.

`CapturePanelController` also owns the persistent floating toolbar, its saved position and the tool chooser's nonactivating panel (`ToolbarChooserPanel.swift`). `FloatingToolbarSurface` selects contextual tools, compact dictation/reading, narration or a temporary screenshot hide without changing the saved floating-toolbar preference (`AppModel.floatingToolbarVisible`, which the panel's and Settings' switches, Window's Show or Hide floating toolbar and the toolbar's Hide toolbar all change); Hide toolbar hides the tools in every mode, while recording, reading and narration keep their own controls. Dictation captures the current Mac target at the toolbar click. Snap & Talk reuses this panel instead of creating a second recording window. A square template status icon is explicitly visible on launch; Window commands recover toolbar access when the menu bar is crowded. Debug QA bundles can provide a bounded temporary `WorkbenchFixtureRoot` to exercise these actual surfaces without using Preview/production storage; release builds ignore it.

The floating toolbar placement owner retains optional edge/fraction/display data in its existing free-position record. `ToolbarEdgePlacement` supplies one drag preview/release result, with whole-edge attachment and corner/centre attraction. `ToolbarGeometry` and the row share horizontal top/bottom/free/corner layouts and vertical side columns. Attached outside edges keep an eight-point inset, with centred expansion along an edge and inward growth at corners. `ToolbarWindowMotion` uses one cancellable frame clock through resizing and orientation changes. `CaptureHUDControls` rejects measurements from an old orientation, keeps result-card sizes separate and shares prospective accessory fitting with the snap guide. `ToolbarHintController` uses one stable rail, inboard at side edges, and suppresses hints during movement. Chooser, prompt, Position and native options panels also open inboard of side columns. Native controls remain disabled until the row fits its host. Named docks keep display affinity alongside their legacy placement. The collapsed target uses one 8-bit alpha step for WindowServer hit routing, with no stacked fills or native shadow.

Carbon registers global keys. Local event handling supports app-focused use. The unified coach receives both modules' assignments and suspends both registrations while recording or practising a shortcut. Validation covers duplicates, a deliberate set of common Mac commands and a temporary OS registration probe. Preference updates must retain the previous value on failure. Practice counts complete key-down/key-up pairs, rejects repeats as extra repetitions, and restores registrations on cancellation, selection change, window deactivation or disappearance. Recording and practice also end when the app resigns active or a menu begins tracking. Current-layout labels sit on an ANSI drawing; this is not a physical-keyboard detector or another-app shortcut scanner.

Snap & Talk has its own editable shortcut. A first press captures only the display containing the pointer through ScreenCaptureKit, with the pointer included, before starting AVFoundation microphone recording. A second press commits the WAV into the user-chosen session folder and queues it through the shared recognition engine. Screenshots and audio commit before transcription, so another section can begin while recognition proceeds sequentially. Interrupted recordings remain visible as unfinished sections; queued work resumes from saved audio after relaunch. The manifest owns ordering, while UUID directories keep reordering non-destructive. `ReadbackOrdering.swift` presents a compact native table with same-table, single-use drag tokens and insertion feedback. Its draft order is separate from storage until Save; `saveSectionOrder` verifies the original active IDs/order and merges the chosen permutation into the latest section records. Cancel and hover never write. Replacement archives prior media inside the section, and deletion moves the whole section into the session's `trash` directory until explicitly emptied. Its handoff menu writes only a task prompt to the clipboard, reveals the local folder and opens a chosen installed AI app; the user still grants folder access and submits the prompt, so Workbench never silently uploads session media.

Speech flow:

```mermaid
flowchart LR
    Input["Microphone or imported audio"] --> Engine["RecognitionEngine<br/>Snapshot selected provider"]
    Engine --> Original["Original transcript"]
    Original --> Cleanup["Optional cleanup<br/>then dictionary"]
    Cleanup --> History["Save completed capture"]
    History --> Output["Edit, copy, guarded paste<br/>or App Intent result"]
```

Microphone capture is capped at five minutes; file import at 30 minutes. Very short or effectively silent recordings are rejected as routine, not as failures (see below). Imported source files are not modified. Failed audio-only recovery can be retained under LocalVoice/SavedRecordings through an atomic same-volume directory move before a fresh recording; recognized-text save failures retain the single-slot guard. The source file for an import is validated before releasing recovery, and selecting the current recovery invokes its owned retry. Each Parakeet request uses a fresh decoder state. A pending hold-to-record permission request cannot later start a stale recording after the key is released.

Automatic paste checks both the original application and accessibility field immediately before delivery, excludes secure fields, and never submits. Rich-text focus resolves only to its nearest editable ancestor; a different field or app is rejected. Supported Electron accessibility trees are enabled only when the application explicitly reports its documented attribute as false. `OpaqueEditorDestination` handles only Sublime Text's observed focused-standard-window shape. Dictation arms its bounded input, application-activation and window/focus observation; an observed change invalidates the captured destination permanently, and idle, cancellation or delivery releases the monitors. Saved Prompts and other unreadable apps do not use it. It sends once and reports Sent to Sublime Text · still copied, without claiming confirmed insertion or creating a recurring unresolved-delivery warning. Scrolling does not invalidate the target; edits, clicks, app changes and timed-out snapshots do. Confirmation reads string, attributed or range text and polls for at most 1.2 seconds after one PID-directed paste; it never retries insertion. Exact text and selection checks cover repeated text and delayed updates. `TextDelivery.System` supplies Accessibility trust, field eligibility, the pasteboard and the ⌘V poster; `TextDeliveryChecks` runs the unapproved path on an isolated pasteboard and asserts one copy with no paste events. `AccessibilitySetup` asks macOS for approval on every click, which shows macOS's request only once and relists Workbench after a reset. It opens System Settings at once, except on a first click while Workbench is in front, when it waits for a request to take focus and opens Settings only if none did; the voice preferences record that first request. `AccessibilitySetupChecks` covers that route with injected effects, including the resign-active signal, and never touches TCC. Captures are saved before delivery. Clipboard restoration requires confirmed insertion and unchanged clipboard ownership; uncertainty leaves the transcript copied for recovery. `AccessibilityBridge` is the one door to the Accessibility framework's element reads, writes and observers; every `AXUIElement*` and `AXObserver*` call is made there, in place on the calling thread, keeping each budget's own messaging timeout and Apple's default for elements without one, because that IPC logs no AXCommon fault in any context (`docs/verification/2026-10-06-ax-bridge/`). The voice listings, which do fault from a Swift task's thread, stay in `MacVoiceCatalog` under its own rule. `scripts/check-accessibility-bridge.py` fails the harness phase when an element call appears outside the bridge, a voice listing outside `ReadingVoices.swift`, or either inside a `Task` closure there.

The nonactivating `CapturePanel` carries recording, processing, cancellation, failure and delivery states in the toolbar's own host without displaying transcript text (#134 T4): at rest only recording adds a dot and voice trace to the icon-free pill. The expanded row retains a fixed Switch tool icon, a separate recording signal and the next action with Cancel in the owning chooser row. Technical failures retain their recovery view (`FloatingResultView`); copied delivery uses a brief `ClipboardCueHUD` and confirmed insertion stays quiet. A dictation that hears no speech (a tap, silence, a sound that is not speech, or speech that came back as no words) is routine, not a failure: `AppModel.endWithoutSpeech` publishes a `CaptureCue`, which shows "No speech heard" and one short hint at the toolbar's place. `CaptureCueClock` lets it go after 1.6 s that the person is not holding it by hover or VoiceOver focus, VoiceOver hears the same words, and any recording of our own stays in capture recovery for Retry. Failures (microphone permission or start, the engine or provider, saving and recovered recordings) keep the explicit 480 × 128 recovery view, available when the toolbar is revealed. A reading that stopped because its audio could not be read keeps its reason, Retry and dismiss in the same way until one is chosen.

Brief feedback shares one lifetime (#134 T5). `NoticeLifetime` counts seconds of visible, unheld time on a monotonic clock (`ProcessInfo.systemUptime`, the timebase of NSEvent and Carbon key events), tied to one event ID: `present` starts it once, pointer, focus, menu and pin holds pause the same remaining value, and `NoticeExpiry` wakes its owner, which ends the notice only if it is still that event and due. Views read a lifetime to draw a countdown ring and report holds; they never start or end it. `FeedbackCoachModel` owns the one coaching card: `request` asks only for a lesson not yet retired in `CoachTips` (the edition's own preferences) and only while the host's `canPresent` says it can be shown; the host shows `CoachCardView`, then calls `didPresent` (which starts the four seconds, retires the lesson and announces it once) or `drop`, which runs the owner's fallback so the gesture still gets its ordinary feedback. `PointerPresence` reports a pointer already resting where a notice appears, which SwiftUI hover misses until the pointer moves, so the card and the receipt HUD start held. New dictation, teardown, sleep and lock remove it. The first lesson is the hold gesture: `VoiceHotkeys` carries each Carbon or NSEvent key timestamp to `AppModel.shortcutChanged`, which times the press that began a Hold attempt as a `HoldGesture`; `stopRecording` asks `HoldLesson.teaches` only after the recorder ran, and a successful hold retires the lesson. `UnresolvedDeliverySlot` keeps one `UnresolvedDelivery` (a failed copy, an unconfirmed paste, a stopped delivery or nothing pasted) in `AppModel`, naming the transcript in History or the draft revision it came from, never the words. `AppModel` hands it `DeliveryRecords` (History and the draft as they are) at each step: a delivered outcome resolves it only when its text equals the record's words now, a draft entry acts only while `draftRevision` is unchanged, `removeTranscript` drops an entry naming that transcript, and every `SavedState` write carries it (optional, so older state decodes, and dropped if a later build's kind cannot be read) only while what is written still holds its words. Launch restores it after capture recovery has settled the draft. The receipt's `clear()` on a new or retried capture and at teardown only ends presentation. `LocalConfirmation` gives `KeyboardCoachModel` and `SnapModel` their four-second ✓ confirmations, classified where the save or export succeeded and announced once through `FeedbackAnnouncement`, which only the running app posts. `AppModel` retains the transcription task and invocation ID, checks cancellation after each asynchronous stage, and keeps the capture gate closed until an engine unwinds. Delivery follows the history commit and is not offered as cancellable. Manual cleanup also guards the draft revision so a delayed result cannot overwrite newer edits.

`TextDelivery.Outcome` distinguishes a successful copy, confirmed insertion and an attempted but unconfirmed paste, and why a copy was not pasted: no Accessibility approval, a changed field or an unreadable one. `ClipboardReceiptModel` stores only delivery metadata and the clipboard generation returned by Workbench's write. It checks that generation while a receipt exists, clears stale cues when another copy occurs, and never reads unrelated clipboard text. Confirmed insertion stays quiet. A copied fallback shows a three-second two-line cue with no Review, pin, word count, dismiss button or countdown. Hover or VoiceOver can hold it for reading. Expiry hides only the cue; still-current clipboard metadata remains in quick controls. A typed paste-attempt flag prevents duplicate-paste suggestions. Saved delivery recovery remains with its owner after the floating cue hides.

Image viewing and editing share the controller described under [Snap, selected history and explicit assistant tasks](#snap-selected-history-and-explicit-assistant-tasks). Its window follows Home during capture; closing Home preserves an open editing draft in its own window.

`WorkbenchHome` presents Library image preparation using immutable bytes and the existing StageKit scene or Persona editor. History and Snap & Talk call `saveCapturedImageToLibrary` with the explicitly chosen image item. That adapter never reads the shared preview’s suspended Snap editor. It verifies the exported file before the Library reference commits, and reports cancellation or partial failure without inventing success. History’s session door opens `ReadbackView` on its existing Sessions sheet; merely opening that picker never reloads the session.

Library resources keep references to original local files. Supported raster images open in the shared image workspace, which holds file access only while reading the image bytes. Other supported formats keep the native `QLPreviewView` route, including SVG. That preview holds its security-scoped access lease until it closes, its resource is removed, the Library view disappears, or Home hides, closes or minimizes. Missing, executable and unsupported inputs are rejected. Search and selection remain owned by the Library.

`DemoLibraryModel.prepareImage` freezes one supported local image with a bounded read while its existing file-access lease is held. Moved or stale references require Locate file; preparation never refreshes a reference or saves an asset. `StageKitController.backdropReplacementView(imageData:title:)` passes the validated snapshot into the existing scene replacement transaction, or explicit first-scene creation when the scene library is empty. `personaImportView(imageData:title:)` uses `PersonaImageImportView` to hold the existing portrait editor session. Cancel writes nothing, and preparing or saving leaves live presentation and Persona copies with their existing owners. `DemoLibraryModel.saveImageToLibrary` exports the supplied rendered PNG to a chosen file, verifies its exact bytes, then saves a bookmarked file reference through the existing Library transaction. An export followed by a Library conflict keeps the file and reports that partial result; no internal Snap or session file becomes a resource implicitly.

`PresentationControlsPolicy` starts collapsed and opens only by click or Command-Slash. Escape closes expanded controls first, then ends the presentation on a later press. Source closes the controls before opening its sheet. `FloatingControlGeometry` shares eight anchors, clamping and snap detection with the recording HUD; each job persists its own placement. The break timer stores only its normalized free position or named anchor plus display identity in `break-timer-placement.json`; countdown state and appearance remain separate. `TimerTransport` is the countdown's one next action for the Draw page, quick controls, Timer menu, floating timer and the toolbar’s activity chooser: Pause and Resume act only on a started countdown with time left, while Start and Restart go through `startTimer`'s admission, activity and window path. Each of those controls keeps the `TimerStep` it showed, the transport and the countdown it belongs to, and performs it only while it is still the next step for that countdown (#174): a Pause or Resume on screen never becomes a Start or Restart, and Restart only ever comes from a control drawn after the countdown finished. Missing displays and resolution changes recover through current visible bounds, while corrupt/future placement data is retained and used only as a temporary default. `CaptureSettings` freezes cleanup configuration, replacements and delivery preferences before recording or file processing. Text refinement is separate from speech recognition and configured in Models. Reduce Motion and Reduce Transparency are honoured. Beginning another activity preserves saved voice recovery with its owner; no recovery badge is drawn on the pill. Window layering is not a guarantee of exclusion from a screen share. See the [interaction specification](product-spec.md).

## Replaceable recognition and reading

`RecognitionEngine` snapshots configuration per request, prevents concurrent transcription, and rejects configuration changes during preparation/transcription. The UI disables model changes while the voice workflow is busy. Provider changes release unused in-memory Parakeet state but retain its downloaded cache.

`LiveVoiceService` reserves the selected engine for a capture and serializes bounded rolling windows across its sources. `LiveVoiceInput` bounds callback delivery; overload or failed inference invalidates live completion while original recording continues. `LiveVoiceSession.swift` defines the view projection and confirmed-word journal. `MeetingModel` and `AppModel` remain the workflow owners and publish the same snapshot shape. `DictationVoiceCapture` reuses `MeetingSystemCapture` to write the recovery store's 16 kHz WAV directly. There is no progressive external paste. The interface, ownership and unverified hardware limits are in [live voice](live-voice.md).

- **Parakeet:** FluidAudio 0.15.6 supplies Parakeet TDT v2 through Core ML. Model preparation downloads/loads the English model when needed. This path needs no background server. A recording longer than one 15-second window has its ending read again and joined on (`TranscriptEnding`).
- **Local model server:** a user-managed OpenAI-compatible audio transcription endpoint. Only exact loopback hosts are allowed; `localhost` is normalised to `127.0.0.1`. Requests use bounded multipart audio upload and require a JSON `text` result. Redirects, credentials in URLs, cookies, persistent cache and configured proxies are excluded. A validated configuration is only “connection checked on use.” Workbench does not install the server, accept arbitrary model files or guarantee that server's own data handling.

There is no fallback from one provider to another. Add an explicit `RecognitionProvider` case and engine dispatch when a new runtime has a clear setup, input, cancellation and availability contract. Do not duplicate recording, history, hotkeys or cleanup inside the adapter. [Provider documentation](model-providers.md) defines limits and tests.

Reading remains separate from recognition. `ReadSelectionService` accepts only the string on the macOS Services request pasteboard. An empty request fails instead of consulting the general clipboard, screen, Accessibility or another window. Every import goes through AppModel's one reading-import decision: the Service's selection and Read aloud in History and Library. A different existing reading stays unchanged behind explicit Keep current / Replace reading controls; importing never starts playback or sends text online. Keep current leaves the draft, player, generation and position as they were. Replace ends the old reading first, cancelling its generation through Cancel generation's path, then discards its audio and progress, so a late result from it is dropped; the new text shows at once and waits for Listen. A Save audio the person chose is never cancelled this way: Replace waits for it and says so, and the save's export stops itself after a minute plus a tenth of the reading's length, so a hung conversion cannot hold Replace until relaunch. Home opens workspaces without reading the clipboard or starting playback. Read keeps its typed playback failure beside the transport; Dictate only shows its own attention and transcript delivery receipt. The existing reading admission and import owners remain unchanged. `ListeningText` prepares the spoken copy and maps it back to the displayed text. `MacVoiceCatalog` lists, resolves and defaults installed voices by identifier; the names `say` lists, and the voices only `say` can speak, are read from `NSSpeechSynthesizer` once per process and only when a saved choice needs them, on the main thread, because that scan looks the Siri-era voices up by language and name and logs for each. `MacSpeechRenderer` renders Mac voices through `AVSpeechSynthesizer` into a growing 16-bit WAV (`ReadingAudioFile`) with word marks, and `ReadingPlayer` plays any source through `AVAudioEngine` while rendering continues; `/usr/bin/afconvert` exports M4A. `NeuralSpeechRenderer` renders the optional neural voices (Pocket TTS through FluidAudio) into the same growing file with one mark per sentence; both renderers are a `ReadingRenderer`, so playback, seeking, cancellation and Save audio are shared. `NeuralVoiceStore` owns the one download and the loaded model, and never downloads in passing. Audio a voice has not rendered yet makes playback wait. A source that throws, or a finished one with less audio than it lists, is read no more and ends the reading once through the player's finish path: playback and pause state clear, the unreadable audio is discarded, the text and voice stay, and Read shows the reason beside Listen with Retry, which makes new audio. That typed failure lasts until Listen, Retry, a replaced draft or Dismiss clears it; the panel and other pages show the same message, and a later, unrelated error does not hide Retry. Voices only `say` can speak keep `/usr/bin/say` with an argument array and a temporary UTF-8 input file. User text is not interpolated into shell commands. Optional Speko reading uses an explicit Keychain-backed key and sends text online only after Listen or Save audio. Its voice catalogue is fetched without reading text; Automatic keeps balanced routing, while a selected catalogue entry pins the provider/model/voice tuple Speko marks as compatible. This TTS adapter is not a transcription provider. New reading or recognition backends should preserve their separate playback/capture and explicit-consent boundaries.

Cleanup offers Original, deterministic Light, and optional Natural editing through Apple FoundationModels where available. Natural candidates are checked for ordered factual tokens, numbers and negation; rejected/unavailable edits fall back to Light. These guards reduce specific risks, not prove equivalent meaning. The unedited text stays available.
