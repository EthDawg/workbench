# Creation, handoff and permission decisions

Reviewed **6 October 2026** against Workbench `c7947a51080ee36255efadbf8dca152c41ded638`, current official documentation and the [synthetic handoff trial](../verification/2026-10-06-handoff-trial.md). This is the current synthesis of the broader creation hypothesis. The [product contract](../workbench.md#history-and-optional-assistance) owns implemented behavior; [issue #63](https://github.com/Ship-Work/workbench/issues/63) owns Snap & Talk input/template/output acceptance. This record is evidence and decisions, not another backlog.

## Product judgment

“Bring material, explain what you want, review a useful result” is a promising organizing principle. The distinctive opportunity is reducing source gathering and repeated explanation while retaining the evidence behind a result. A new general-purpose creation surface is not yet justified by the experiment: both routes received prepared material, so the trial removed much of the human work this hypothesis might save.

Build on selected History, Snap & Talk, explicit handoff and the receiving assistant's existing file tools. Start from supported inputs and one concrete outcome. Add an input type when its preservation, preview, capability limits and failure path can be verified. A file appearing in a drop zone does not establish that it was understood. Presentation-style feedback must distinguish visible slide design and transcript wording from claims requiring actual audio or video.

## What Apple's privacy screenshots mean

The screenshots correspond to [WWDC26 session 206, app management](https://developer.apple.com/videos/play/wwdc2026/206/). Apple describes organization-recommended permissions grouped into one consent prompt, with an organization justification and user choice. Selecting Not Now retains ordinary per-component requests. App settings and Safari website settings use separate declarative configurations.

The [deployment reference](https://support.apple.com/guide/deployment/depd567c9ffa/web) describes supervised iOS/iPadOS/macOS 27, `com.apple.configuration.app.settings` → `Privacy`, and Safari camera/microphone defaults under `com.apple.configuration.safari.settings`. It still carries a pre-release qualification at this review. The advertised app list includes Accessibility, Bluetooth, Camera, Dictation, Local Network, Location and Microphone; it does not include Screen Recording. This is deployment research, not a tested Workbench integration.

A managed deployment would additionally need the [AppSettings schema](https://developer.apple.com/documentation/devicemanagement/appsettings), [privacy schema](https://developer.apple.com/documentation/devicemanagement/appsettingsprivacyobject) and [permission dictionary](https://developer.apple.com/documentation/devicemanagement/appsettingsappdictionaryobject). The documented Mac path is for AppKit-based apps and uses user scope. Accessibility is macOS-only; LocationAccuracy is iOS/iPadOS-only. Verify exact bundle/signing identity and final per-platform availability; keep Preview and Stable distinct. Apple's “Dictation” permission name is not evidence that Workbench's local transcription requires that permission.

For ordinary installations, keep the existing microphone, Accessibility and ScreenCapture owners and explain access at the action that needs it, following [Apple's privacy guidance](https://developer.apple.com/design/human-interface-guidelines/privacy/). Permission work must preserve denial/cancellation/restricted states and re-check on return to the app. Do not add a setup-wide permission requirement for workflows that need no capture access. No management profile, new permission request or privacy reset was performed for this research.
