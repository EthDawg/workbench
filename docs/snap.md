# Snap

Snap is a deliberate Mac capture utility. Region and Window use Apple's interactive selector; Screen captures the display under the pointer. Workbench hides its capture controls while acquiring the image. Screen Recording access remains a macOS permission. Cancel or Escape creates no history item, and the selector writes only to a private temporary location removed when capture finishes. No automatic Desktop image is created.

Every capture door finishes the same way. From Home, the Snap page, the menu-bar panel, the floating toolbar or the Snap shortcut, the Workbench window comes forward on the Snap page with the new capture open in the editor, even when the window was minimised or closed. A problem acquiring the image is shown there too, where it can be acted on. Cancel or Escape in the selector shows nothing new: the window returns to how it was and the app you were in comes back to the front. Save & Copy of a capture that began in another app returns to that app, ready to paste; Save and Cancel stay in Workbench. An editor left open, for example in a minimised window, is brought back by the next capture instead of silently blocking it. `SnapCaptureHost` owns this completion path; `SnapModel` remains the only draft owner.

Without Screen Recording access, Region, Window and Screen stop before anything is hidden or captured. Each door opens the Snap page, which says in plain words that Screen Recording is off for Workbench and offers Paste image, Import image… and Open System Settings…; the panel row, toolbar hint and Home's Snap card say so too. Every saved Snap still opens, copies, edits and hands off. Coming back from System Settings with access still off, Snap and Snap & Talk add: "If Workbench already shows as allowed there, quit and reopen it," since macOS applies a grant to a running app only after it reopens. Workbench asks macOS only from the person's own capture, which lists it in System Settings, and never changes the permission itself; a managed Mac may keep screen capture off, so importing an existing image is offered as an ordinary alternative, not a way around that policy. `ScreenCaptureAccess` is the one place Snap and Snap & Talk read and request the permission, so checks use a fixed answer.

The desktop Snap workspace owns quick crop, pen, arrow and rectangle annotations, titles, optional notes and tags. Paste image and Import image open the same unsaved editor. Save retains the image in History; Save & Copy also places the rendered PNG on the clipboard. Closing or cancelling an unsaved editor leaves history unchanged. Copy and explicit Export use the saved crop and annotations. The original image remains available for later editing; imported external files are never changed.

Capture images open one read-only preview: Snap cards, History's Snap rows, Home's latest Snap, Snap & Talk sections (including failed and Recently Deleted ones), the images a Hand off review is about to share and the saved copies a Hand off task used. The Reorder list keeps its thumbnails for arranging sections. Click the image, press Space or Return on it, or choose **View image** in its More or context menu. The preview opens fitted to its window, with **Actual size** (one image pixel per screen pixel), zoom (⌘+, ⌘−, ⌘0 for actual size, ⌘9 to fit, or pinch) and **Close** or Escape. It shows the current revision, the rendered edit of an edited Snap, and says when a file is missing or changed outside Workbench instead of failing silently. It reads a file only when opened and decodes it on its own queue, at most about twice the display's size, so an unusually large import stays within memory; Actual size still means the image's own pixels. It never edits, moves or copies the file, and closing it stops a decode that has not started; the page underneath keeps its section, scroll and selection. Editing stays a separate action: **Edit…** on a Snap card or row, and Replace screenshot in a section's More menu.

## Desktop screenshots

**Add image → Import Desktop screenshots…** gathers screenshots taken with the macOS shortcuts. It lists only files macOS marked as screen captures (the `kMDItemIsScreenCapture` attribute, so any language and never ordinary images), confirms the count, adds each to History with its original date and exact PNG bytes, and only then moves the file to the Trash. An image already in History is only cleared, so a retry after a failed Trash move never duplicates a Snap. An unreadable Desktop is reported, never shown as empty. The imported Snaps are selected, so Organise… can find repeats and themes next. App Store builds omit this choice.

## New screenshots off the Desktop

**Keep new screenshots off the Desktop** is an explicit, reversible change to a macOS setting. It records the current macOS screenshot location, points it at `~/Pictures/Workbench Screenshots`, and asks macOS to apply it (the menu bar refreshes once). While Workbench runs, settled files that macOS marked as screen captures move from there into History, each saved and read back before its file goes to the Trash. An open Snap editor does not pause this: the draft keeps its own image, and new screenshots appear in the grid behind it. Turning it off restores the previous location unless the person has chosen another one since; a later manual change pauses collecting instead of fighting it. App Store builds omit this choice.

## Ownership and preservation

`SnapModel` is the app's single Snap owner. `SnapStore` keeps one directory per stable UUID in the current Workbench edition's `Snaps` support directory. `original.png` is immutable; edited PNGs have distinct immutable filenames. A versioned `snap.json` links the original, rendered image, non-destructive crop/marks, metadata and an optional archive date. A per-record revision rejects stale editor saves, including after an incidental history reload. Atomic metadata replacement follows private media writes, and oversized metadata is rejected before commit. Unreadable or newer-format records produce recovery notices; valid records remain available and no automatic eviction runs.

Archive is reversible metadata. Restore returns the same UUID and files to history. Snap does not automatically delete original images, older edits, archived captures, earlier narrated-session files or a running task's input bytes. This first version has no permanent-delete command. The product remains account-free and works locally without a provider.

Search covers title, source type, notes, tags and the text visible in each image. Every search term must match. After a Snap is saved, Vision reads its text on this Mac in the background and computes a feature print for spotting repeats; both live in `derived.json` beside the Snap, keyed to the image digest they came from. They never enter `snap.json`, so they cannot collide with an open editor, and a missing or stale file is simply rebuilt. Filtering does not discard selection; the footer distinguishes selected Snaps hidden by the view, archived Snaps and unavailable references. The host supplies a binding backed by the common history selection owner, preserving transcript references when a Snap is selected or cleared. Saved selections contain UUID references rather than exported folders. Missing or archived selected images stop handoff with a visible explanation and a deliberate action to exclude those references while preserving other selected evidence. The saved selection changes only through Update. Hand off starts from History's selection footer; the Snap page's Use selected keeps Add to Snap & Talk, Organise… and Archive.

`SnapModel.handoffSnapshots(ids:)` returns frozen original/rendered bytes and metadata in saved-history order. One request allows up to 100 Snaps and 256 MB of image bytes. The common handoff flow owns destination, selected-content review, provider status, task receipts and outputs. Editing or archiving a source after dispatch cannot change that job.

## Snap & Talk composition

Create or open an existing Snap & Talk session, then add selected history images. `SnapReadback` copies original and rendered PNGs plus source identity into new portable section directories and appends them to the existing v1 manifest. It preserves current section order, custom skills, frozen private packs and all earlier sections. The session remains usable away from this Mac's Snap store.

Imported sections are ready with optional editable notes and no invented audio or original transcription. Record narration is an explicit separate action. The existing capture-and-narrate shortcut keeps its established behavior. Re-adding the same source bytes and metadata skips the existing section, including one in Recently Deleted; restoring that section is explicit. A changed source produces a new frozen section without replacing the earlier version. Invalid batch inputs are checked before any section is created.

The host also wires `ReadbackModel.onSaveCapturedSnap` to `SnapModel.saveNarratedCapture`. A new screenshot from the existing Snap & Talk shortcut first enters this same History, then becomes a portable narrated section with a source receipt. Adding it back to that session skips the duplicate. If the session addition fails, the app identifies the saved capture in History for retry. Earlier sessions are not bulk-imported or rewritten. Narration, section replacements and custom session edits remain owned by their portable session; they never mutate its original source Snap.

With Screen Recording off, a new Snap & Talk capture stops with that explanation before the screen is touched, and its page, panel row and toolbar hint say so. A session's screenshots, narration, typed notes and Add from Snap History keep working; with the microphone off, narration recording stops the same way while typed notes still work.

## Organisation and synthesis

Organise reviews the exact selected UUIDs. Its local overview groups saved titles and notes by their existing tags and links to each immutable source image. Byte-identical rendered images become duplicate proposals. Captures whose feature prints fall within `SnapAnalysis.repeatDistance` of an earlier capture are proposed as repeats of it, because a clock or pointer usually changes between otherwise identical screenshots; low-value images still require human judgement. Archive reviewed repeats is explicit and refuses changed sources or a changed retained copy. Originals remain recoverable.

The host supplies the stable saved-selection UUID when a named selection is deliberately being reviewed. Its current document under `Snaps/Reviews` keeps the same path when that selection is updated or renamed. Ad-hoc selections use the selected UUID set as their identity. Neither flow creates a batch folder. A local overview links to the Snap library; synthesis links are rebased to the immutable selected images in the existing handoff job. Portable sharing uses the complete handoff snapshot. Archived duplicates are not proposed again, and Archive and exclude deliberately removes only the reviewed duplicates from the current selection.

Hand off for synthesis opens the common selected-content review with a bounded instruction to create one useful themed document, link claims to source UUIDs/images, distinguish captured claims from current facts and inference, and list exclusions with reviewed/retained/excluded counts. The prior document can be read and included as reference; actual saved names and archive choices remain authoritative. A successful task keeps its original reply and updates the current review only if that document has not changed since preparation. A later failure leaves the current document available. Deliberately using another result as the current review preserves intervening edits in that task's outputs. History groups these tasks under one review and retains earlier replies. Synthesis cannot automatically apply cleanup; a result or summary is never authority to delete evidence.

## Verification boundaries

`bash scripts/test-snap.sh` compiles the actual storage, renderer, organisation and portable-session importer with synthetic fixtures. It checks crop pixels and dimensions, annotation output, visible-text search and repeat proposals on synthetic screens, immutable originals/snapshots, stale-save refusal, serialized-size limits, private file modes, corruption/symlink refusal, reversible duplicates, stable result paths, optional narration, repeated import, ordering and unchanged pack/skill bytes. It also checks that screenshots keep arriving while a draft is open, without touching the draft or a later manual screenshot location. `LocalVoice --check-snap-capture` drives the host's completion path for every door, window state and app in front with a synthetic image source, then checks that the real Snap page presents the editor for the captured draft while Home does not, in a window that is never on a display.

These checks do not establish installed capture permissions, region/window selection, clipboard delivery, keyboard/VoiceOver behavior, multi-display capture or the combined provider round trip. Native acceptance must also confirm a fresh Snap & Talk shortcut capture appears once in History, adding it back does not duplicate its section, and canceling narration retains the image. The sole Preview integration owner verifies those journeys on the signed candidate, records Copy build details and follows [the shared install/update workflow](updating.md). Source implementation, automated checks, native acceptance and public release are distinct states. Track the combined delivery in [issue #112](https://github.com/EthDawg/workbench/issues/112).

`LocalVoice --check-capture-preview` opens synthetic edited and archived Snaps, replaced, failed and recently deleted sections and a task's saved copy through the preview's loader and its real window, off every display: current revisions, missing and changed files, fit, zoom keys, Escape, and no file changed. The installed preview's window, pinch, focus and VoiceOver still need native acceptance.
