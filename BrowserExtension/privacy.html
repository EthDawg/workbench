Workbench Preview for Chrome

Privacy and permissions · 20 September 2026

Your Workbench browser records stay on your device.

Workbench Preview for Chrome saves named web destinations and returns to them in their paired Chrome profiles. It requires the matching Workbench Preview companion for macOS. Ethan Harley publishes this open-source extension.

What the extension handles

The extension handles the destination names and Chrome profile labels you enter, a generated profile identifier, the addresses you choose to save, and temporary tab/window identifiers used to focus a destination. Opening the popup reads the current tab’s address locally so you can review it. For Switch to destinations, query parameters and fragments are removed before an address is saved or sent to the companion. Browser setup packs preserve ordinary query parameters and fragments, while rejecting known credential-bearing query keys. Review their complete addresses before applying or sharing a pack. Usernames and passwords embedded in an address are rejected.

To find a saved destination, the extension checks permitted tabs’ current or pending addresses. It does not read page content, forms, passwords, cookies or browsing history. It does not sign in, rotate passwords or confirm which account is authenticated. Page titles are not used as destination names.

Optional browser setup reads the bookmark tree locally to identify a writable local root and check only Workbench-owned node receipts. It sends counts, a root label, fixed status notes and a review token to the companion; it does not export your bookmark tree. Applying an explicitly reviewed pack creates folders/bookmarks or updates unchanged recorded nodes. It never removes existing bookmarks, adopts same-named folders, or overwrites detected manual edits. Chrome cannot make the check and write atomic with a simultaneous manual edit.

Where this data goes

Chrome stores the profile label, generated identifier and pairing state locally in that profile. Browser setup also stores the chosen root ID, owned bookmark node IDs and their last title/address/parent, operation receipts and an interruption journal in local extension storage. Five-minute review tokens live only in the service worker and expire on worker restart. The extension does not write these records to Chrome Sync. Tab bindings and an unfinished save draft stay in Chrome’s session storage. A permission-step draft can be restored for 15 minutes; an expired draft is not used and may remain in session storage until overwritten or the browser session ends.

The extension sends chosen names, saved addresses and profile labels to the local Workbench companion through Chrome’s native-messaging connection. The companion owns the canonical Saved resources records on your Mac and returns the destination list to your connected Chrome profiles. Browser destinations are not part of Workbench’s optional photo or scene sync.

This feature has no developer-operated data server, analytics, advertising, sale of data or transmission of destination records to Ethan Harley or other third parties. Chrome Sync is not used for Workbench extension records. Setup writes only to roots currently marked local by Chrome; later Chrome Sync choices can change whether your bookmarks are synced. When you open a destination, Chrome contacts that website normally; the website’s own policies apply. Visiting the companion website or support links also makes a normal web request to that provider.

Workbench’s use of data received through Chrome APIs complies with the Chrome Web Store User Data Policy, including its Limited Use requirements.

Why Chrome asks for permissions

  • Communicate with cooperating native applications: connects only to the Workbench native host so Saved resources can route a destination to its paired profile.
  • Current tab access: reads its address when you open Workbench, so you can review and save that tab.
  • Local storage: keeps profile pairing, session tab bindings and a temporary save draft.
  • Alarms: attempts to reconnect a paired profile after the companion disconnects. It never retries an opening command automatically.
  • Optional bookmark access: requested from the Browser setup page only when you click Allow. Chrome grants access to all bookmarks in the profile; Workbench restricts its operations to a selected local root and its recorded nodes. Revoking access blocks bookmark setup while Switch to remains available.
  • Optional access to a site: requested only when you choose to allow that site. It lets Workbench identify and focus its saved tabs. A new subdomain needs a new grant. Although Chrome describes this as site access, the extension uses tab addresses and does not inspect or change the page.

Incognito is disabled. The extension does not request unrestricted tab-history, cookie, password, scripting or content-script access.

Your controls and deletion

Open launch tabs creates a new ordinary window in the selected connected profile. It never changes Chrome startup or New Tab settings, sign-in, saved passwords or cookies. Launch request IDs are recorded before opening and never replayed automatically. Interrupted bookmark writes block further bookmark application until their uncertain outcome can be reviewed; no name-based recovery or destructive rollback runs.

Review the exact saved address and choose an audience-safe name before saving. Manage site access or remove the extension in Chrome’s extension settings. Removing the extension removes its Chrome-managed local data and ownership receipts, but does not remove bookmarks it created; a reinstallation cannot recognise those as owned bookmarks. Existing bookmarks remain yours to manage in Chrome. Closing Chrome clears session data. Saved resources in the Mac companion is separate: removing the extension does not delete those records. Manage those saved items in Workbench. Device backups follow your own system settings.

For privacy questions, use Workbench support. Issues are public, so leave out private destinations and customer details. Use private vulnerability reporting for security-sensitive concerns.
